## 📦 本分支新增内容

### 1. 模型测速（首字延迟 TTFB）

给每个「渠道 × 模型」测出真实的**首字延迟**，作为选型与运维的依据。

- **探测方式**：向上游发送最小请求（提示词 `ping` + `max_tokens=1`，流式），
  收到首个数据分片即断开连接——单模型一次约消耗 **2~3 token**。
- **串行探测**：数字不受并发干扰，可横向对比。
- **落库**：结果写入 `model_speeds` 表（迁移 0045），每组合只留最近一次。
- **展示**：
  - 管理端：渠道行内「测速」按钮、独立测速页 `/admin/speedtest`；
  - 模型广场：公开表格的「首字延迟」列、内嵌广场卡片的延迟徽章
    （<1s 绿 / 1~3s 灰 / >3s 橙），详情弹层附测速时间。
- **公示开关**：「系统设置 → 测速」可关闭对普通用户的延迟公示；
  **管理员始终可见**（豁免开关，不影响站长自己核对数据）。

### 2. 测速后自动屏蔽无权限模型

测速发现上游**确定性拒绝**的模型，自动从渠道清单移除。

- **判据**：仅 403（无权访问）/ 404（模型不存在）——重试也不会好的失败。
- **不误杀**：超时、429、5xx、网络错误属暂时性故障，绝不移除。
- **安全护栏**：
  - 只移除**本次实测**的模型；
  - 若会把渠道清单清空则放弃（空清单 = 支持全部模型，语义相反）；
  - 写库失败自动回滚清单。
- **可配置**：系统设置 → 测速 → 「自动屏蔽无权限模型」（默认开启）。
- **可见性**：测速结果标记「已移除」徽章，响应携带 `blocked_models` 清单。

### 3. 渠道表单一键获取模型列表

编辑渠道时点「从上游获取」：直接调上游 `/v1/models` 拉取模型清单，
**合并不覆盖**已有 textarea 内容（避免误清空手工维护的清单）。

### 4. 配套修复

| 修复 | 影响 |
|---|---|
| 上游地址自带版本段时去重端点 `/v1` 前缀 | 修复 `/v1/v1/chat/completions` 404——目录里 NVIDIA/OpenAI/DeepSeek/Moonshot 等默认地址此前**全部无法直用** |
| 密钥池按导入顺序分配 ID | 修复插入走 map 迭代导致的池顺序随机（轮询次序漂移、凭据路由间歇配错钥匙） |
| 测速弹层关闭态渲染死循环 | React effect 依赖数组身份 + 无条件 setState 的无限渲染，改用内容键 |
| 广场公示开关不再挡住管理员 | 见上文「豁免」 |

## 🚀 快速上手（本分支功能）

1. 启动服务后进入后台 **系统设置 → 测速**：确认「启用模型测速」开启，
   按需调整单模型超时（5~120s）、单次模型数上限（1~500）、自动屏蔽开关。
2. **渠道管理**：点渠道行内的「测速」按钮，或在 `/admin/speedtest` 选渠道批量测。
3. 测完到 **模型广场**（`/models` 或后台 `/admin/models`）看延迟徽章。

### 管理端接口

```
POST /api/admin/channels/{id}/speedtest
     Body: {"models": ["m1", "m2"]}   # 空 = 测渠道全部模型
     Resp: items[{model, ok, status_code, ttfb_ms, blocked, message}],
           blocked_models[...]
```
